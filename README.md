# RL Education — интерактивный исследовательский практикум

Конкурсный образовательный симулятор для изучения принятия решений: четыре лабораторные работы, четыре презентации по шаблону Финансового университета, модульные Python-примеры и интерактивный сайт. Сквозной результат — собственный проект на любую обоснованную тему по обучению с подкреплением.

**Сайт:** https://petrnikitin20.github.io/RL_education/  
**Автор:** Никитин Пётр Владимирович, кафедра искусственного интеллекта Финансового университета.

## Что включено

1. Бандит + CEM: ε-greedy, UCB1, Thompson sampling, cumulative regret; затем случайные позиции собаки и костей, пространства из 4/8/12 действий, элитные траектории и таблица политики.
2. Табличное RL на MOEX: Q-learning, SARSA и Expected SARSA; OHLCV, momentum, RSI, MACD, ATR, Bollinger bandwidth, volatility, drawdown и объём.
3. DQN, Double DQN и Dueling Double DQN: выбор российской компании, временное разбиение, комиссии, риск-метрики и сравнение политик.
4. Multi-agent RL: портфель из 3–6 российских компаний, Market, Risk и Allocation Agent, динамические веса и сравнение с равновзвешенным портфелем.

Веб-демонстрации выполняются полностью в браузере. На странице одновременно открыт один пример; остальные выбираются по ссылкам в верхнем меню. После лабораторной №4 отдельной пятой ссылкой открывается итоговый проект на любую тему по RL. Для каждого примера приведены постановка задачи, описание данных, анимация, прогноз до запуска, динамический вывод, входная диагностика, итоговый тест и экспорт протокола. Режим преподавателя показывает временное разбиение и методические комментарии.

## Мастерство применения искусственного интеллекта

ИИ используется как исследовательский помощник, а не как источник готового результата. В каждом стенде размещены хороший и плохой промпты, черновой ответ ИИ и проверка студентом. Интерактивный журнал фиксирует модель и версию, дату, параметры, промпт, источник данных, тип результата и метрики; записи сохраняются локально в браузере и экспортируются в JSON.

Правила практикума требуют проверять факты и ссылки по первичным источникам, раскрывать значимое участие ИИ, не передавать персональные данные и оценки студентов внешним моделям и явно различать реальные данные, демонстрационные результаты и синтетические значения.

После четырёх лабораторных работ студент или команда до трёх человек защищает итоговый RL-проект. Оцениваются воспроизводимый эксперимент, архитектура, абляции и логика выбора модели, а не только лучшая метрика.

Лабораторные №2–4 используют один зафиксированный снимок публичного MOEX ISS: дневные свечи TQBR за 2022–2025 годы для SBER, GAZP, LKOH, NVTK, GMKN и MGNT. Файл `data/moex_daily.json` можно обновить скриптом `tools/fetch_moex_data.py`. В лабораторной №2 Q-таблица действительно обучается в браузере; стенд №3 прозрачно оценивает эталонные DQN-политики, а полноценное обучение нейросетей выполняется в Python.

## Локальный запуск сайта

```bash
python -m http.server 8000
```

Откройте `http://localhost:8000`.

Прямое открытие `index.html` через `file://` не подходит: браузер блокирует загрузку JSON. Используйте локальный HTTP-сервер или GitHub Pages.

## Обновление данных MOEX

```bash
python tools/fetch_moex_data.py
```

Используется публичный endpoint дневных свечей MOEX ISS без API-ключа. В отчёте обязательно указываются период, режим торгов, дата среза и тикеры.

## Запуск Python-примеров

```bash
python -m venv .venv

```

Примеры — каркасы для лабораторной работы: студенту необходимо добавить журналирование, воспроизводимый эксперимент, временное разбиение данных, baseline, несколько random seed и доверительные интервалы.

## Корректная оценка торгового агента

- Делить данные только по времени: train → validation → test.
- Нормализатор и признаки обучать только на train.
- Учитывать комиссию, проскальзывание и ограничение ликвидности.
- Сравнивать с Buy & Hold и простой rule-based стратегией.
- Отчёт: cumulative return, annualized volatility, Sharpe/Sortino, maximum drawdown, turnover, число сделок.
- Не делать вывод о будущей доходности по одному историческому периоду.
- Выбирать гиперпараметры только по validation; test открывать один раз после фиксации конфигурации.
- Повторять обучение с несколькими seed и сообщать медиану и разброс.
